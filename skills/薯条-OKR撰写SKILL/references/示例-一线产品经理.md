# 示例：一线产品经理的季度 OKR（虚构）

人名、项目名都是虚构的，流程和写法跟真实案例一样。

## 1. 链路和 @本人的 KR

| 层级 | 人 | @本人或相关的 KR |
|---|---|---|
| CEO | 老板 | O4 KR4 AI 原生组织：新增 ≥3 个高价值 AI 场景 |
| 产品中心 | 中心负责人 | O2 让 C 端收益看得见、AI 策略讲得清；O4 KR5 产品团队沉淀 AI 辅助竞品追踪、VOC 归因等场景 |
| 软件产品部 | 部门负责人 | O1 KR2 AI 体验：完成 AI 助手与策略解释升级 **@小林**@小周 |
| 直属 | 组长 | O3 KR3 PRD Lockdown：会员成长体系、多端登录、新客导购 **@小林**；O5 KR3 VOC 需求 PRD **@小林** |

## 2. 三类输入

| 类别 | 内容 |
|---|---|
| 必须承接 | AI 助手与策略解释；会员成长体系；多端登录；新客导购；VOC 需求 PRD |
| 组内模板 | O 按阶段命名（Lockdown / Go-live / VOC），统一的 Soft Skills O |
| 本人工作（周报） | 新客导购 MRD / PRD；B 端 Feature Tree 打分；AI 辅助评审工具 |

员工确认：B 端 Feature Tree 不放进个人 OKR，它的权重分给 O1 和 O2。

## 3. 定稿（表格版）

| O（权重） | KR（权重） | 对齐到 | 来源 |
|---|---|---|---|
| O1 MRD/PRD Lockdown（35） | KR1（40）新客导购：11 月【待确认】前与市场部锁定产品推荐、收益测算与营销口径，拿到合规结论；PRD Lockdown 并通过研发评审，进入版本排期 @小许<br>KR2（30）会员成长体系：12 月完成 MRD + PRD Lockdown，勋章与成就方案通过评审 @小周<br>KR3（30）多端登录：12 月完成 PRD Lockdown，写清登录规则、冲突处理与安全边界，研发内审通过 | 组长 O3 | 上级 @ |
| O2 让用户看懂 AI 策略（30） | KR1（50）11 月完成 AI 助手与策略解释现状盘点：竞品对标、相关 VOC 归因，输出 MRD<br>KR2（50）12 月完成 PRD Lockdown：用户能在 App 里看到"为什么此刻充 / 放电、今天省了多少"，研发与设计评审通过 @小周 | 部门负责人 O1 | 上级 @ |
| O3 VOC 追踪与 AI 辅助评审（25） | KR1（60）Q4 完成分配给我的"重要紧急且实现难度低"VOC 需求 PRD，研发内审通过<br>KR2（40）AI 辅助评审工具在 ≥3【待确认】个真实需求评审中使用并沉淀报告 | 组长 O5；中心 O4 KR5 | 上级 @ + 本人工作 |
| O4 Product Manager Soft Skills（10） | 组内四条原文，各 25 | — | 组内模板 |
